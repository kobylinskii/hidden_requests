# Сканер скрытых HTTP-запросов в Docker

Весь инструментарий (BFScan, Frida-клиент, androguard-срез, принудительная
активация) упакован в один образ. **Устройство/эмулятор в контейнер не входит**:
Genymotion — это GUI-VM на хосте, пентестер кликает в её окне. Контейнер цепляется
к устройству по `adb connect`, Frida общается с `frida-server` на устройстве через
adb.

```
APK ─▶ [ контейнер hidden-scanner ]                 [ хост ]
        1 пакет из APK            ◀── adb/frida ──▶  эмулятор/телефон
        2 BFScan → эндпоинты                          + frida-server (та же 17.23.3)
        3 trace.py ◀─ пентестер кликает в окне эмулятора: трафик + КАРТА ПАРАМЕТРОВ (Ctrl-C)
        4 diff → скрытые запросы
        5 slice → срез скрытых
        6 activate → принудительный вызов (attach), скрытые наполняются реальными
                     значениями из карты параметров (--seed) вместо заглушек
        └─▶ отчёт: какие скрытые, сколько дёрнуто, с какими данными
```

## Предварительно (на хосте)
* Эмулятор/устройство с **root** и запущенным `frida-server` **версии 17.23.3**
  (ровно как frida в образе). Пример (Genymotion): `adb -s 127.0.0.1:6562 shell
  'su 0 /data/local/tmp/frida-server17 &'`.
* Знать adb-адрес устройства (`adb devices` → напр. `127.0.0.1:6562`).

## Сборка
```bash
./build-agents.sh            # ПЕРЕД docker build, если правил *.js (frida 17)
docker build -t hidden-scanner .
```

> **Критично:** шаг 6 (`activate`) грузит скомпилированный `build/activate.js`, а не
> исходник. Образ печёт `build/` как есть (`COPY . /app`), поэтому после любой правки
> `activate.js`/`hook.js`/`prelude.js` нужно сперва `./build-agents.sh`, иначе в образе
> останется старый бандл и правки не подействуют (симптом: ожидаемое поведение агента
> не наступает, хотя исходник изменён).

## Запуск
```bash
docker run --rm -it --network host \
  -v "$PWD/apk:/work/apk" -v "$PWD/out:/work/out" \
  -e ADB_DEVICE=127.0.0.1:6562 \
  hidden-scanner /work/apk/приложение.apk
```
* `--network host` — чтобы adb/frida из контейнера достучались до adb-порта
  эмулятора на хосте (Linux). На macOS/Windows вместо этого
  `-e ADB_DEVICE=host.docker.internal:6562` и пробросьте порт.
* `-it` — обязателен: на шаге 3 терминал ждёт, пока пентестер исследует приложение
  и нажмёт `Ctrl-C` по насыщении.
* APK монтируется в `/work/apk`, отчёты пишутся в `/work/out` (на хосте — `./out`).

## Переменные
| env | смысл |
|---|---|
| `ADB_DEVICE` | adb-адрес устройства (обязательно) |
| `TRACE_APPEND=1` | дописать трафик к существующему `out/<pkg>.dynamic.jsonl` |
| `HIDDEN_IN=<путь>` | старт СРАЗУ с готового списка скрытых запросов (пропустить BFScan+сбор трафика+diff); файл должен быть снят с той же сборки APK |
| `SLICE_IN=<путь>` | старт СРАЗУ с готового среза (пропустить BFScan+трафик+diff+slice) — исключает память-ёмкий androguard-шаг; рядом в out/ полезен hidden.jsonl для привязки matched |

### Старт с готового списка скрытых запросов
Если список скрытых уже есть (например из прошлого прогона — `out/<pkg>.hidden.jsonl`
или бэкап), можно пропустить сбор трафика и сразу делать срез+активацию:
```bash
docker run --rm -it --network host \
  -v "$PWD/apk:/work/apk" -v "$PWD/out:/work/out" \
  -e ADB_DEVICE=127.0.0.1:6562 \
  -e HIDDEN_IN=/work/out/приложение.hidden.jsonl \
  hidden-scanner /work/apk/приложение.apk
```
(hidden-файл тоже монтируй в контейнер — например положи в `./out`, тогда путь
внутри будет `/work/out/...`.)

## Что на выходе (в `./out/`)
* `<pkg>_methods.md` — все статические эндпоинты (BFScan).
* `<pkg>.dynamic.jsonl` — трафик, собранный пентестером.
* `<pkg>.params.jsonl` — **карта параметров**: реальные значения (листья тел
  запросов/ответов и URL), снятые из того же прохода исследования. Шаг 6 берёт
  из неё значения для пустых полей скрытых запросов (имя+ресурс совпали) —
  **повторно прокликивать приложение не нужно**, один проход на шаге 3 кормит
  и diff, и карту. Ответы снимаются `peekBody` (не ломает трафик приложения);
  сырые тела не хранятся — только примитивные листья, мусорные запросы инертны.
* `<pkg>.hidden.jsonl` + `.report.txt` — **скрытые запросы** (в коде есть, не вызваны).
* `<pkg>.slice.jsonl` — срез скрытых (call-sites, стражи, провенанс аргументов).
* `<pkg>.activation.jsonl` + `.report.txt` — **итог**: какие скрытые запросы,
  сколько удалось принудительно вызвать и с какими данными
  (`[а]` достижим / `[б1]` реальные app-данные / `[в]` наполнено заглушками).

## Замечания
* Приложение должно быть установлено на устройстве; если нет — скрипт поставит
  APK (`adb install`) сам. Статика и динамика снимаются с одной сборки APK.
* Frida на устройстве и в образе обязаны совпадать по версии (17.23.3), иначе
  trace/activate не поднимутся.
* Шаги 1–2 (пакет, BFScan) работают и без устройства — полезно проверить образ:
  `docker run --rm -v "$PWD/apk:/apk:ro" --entrypoint ./bfscan.sh hidden-scanner /apk/приложение.apk /dev/stdout`.

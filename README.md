# Сканер скрытых HTTP-запросов Android

Сканер сопоставляет объявления HTTP-запросов в APK с вызовами, которые Frida
зафиксировала за сеанс. Для каждого объявления со статусом `not_observed`
он печатает тело из каталога BFScan, сохраняет обратный DEX-срез аргументов и
считает стражи — условные переходы на путях к вызову метода.

```text
BFScan → *_methods.md ───┐
                         ├─ request_pipeline.py → *.hidden.jsonl
Хуки → *.dynamic.jsonl ──┘                              │
                                                   not_observed
                                                        ├─ Тела из каталога BFScan → *.bodies.jsonl
                                                        ├─ Обратные срезы аргументов → *.request-slice.jsonl
                                                        └─ Стражи и стоимость активации → *.reasons.jsonl
                                                                                        → *.reasons.report.txt
```

| Результат | Что внутри |
|---|---|
| `<pkg>.hidden.jsonl` | Все объявления со статусами `observed` и `not_observed`, с оговорками в `confidence_caveats` |
| `<pkg>.bodies.jsonl` | По одной записи на скрытое объявление. Поле `body` содержит текст примера BFScan. Если примера нет, `body` равно `null`. `confidence_caveats` переносится из списка объявлений |
| `<pkg>.request-slice.jsonl` | Места прямого вызова, типы аргументов и графы происхождения значений. Для объявления без прямого вызова указан `no_direct_call_sites` |
| `<pkg>.reasons.jsonl` | По одной строке на скрытое объявление. Число мест вызова и стражей, точность оценки, глубина и причины остановки |
| `<pkg>.reasons.report.txt` | Пакет и версия, сводка по объявлениям и раздельные списки точных, нижних и неопределённых оценок |

Ключ для связи отчётов — пара `build` (SHA-256 APK) и `declaration_id`.
| Статус | Значение |
|---|---|
| `observed` | В трассе найден вызов с точной парой `класс->метод` и DEX-дескриптором. `confidence_caveats` пуст. |
| `not_observed` | Точного совпадения в трассе сессии нет. В бинарной статистике это статика минус динамика. |

`confidence_caveats` перечисляет ограничения, которые влияют на уверенность
в выводе. Возможны несколько оговорок одновременно:

- `dex_identity_unresolved` — DEX-дескриптор объявления не удалось установить.
- `artifact_incomplete_or_unverified` — каталог либо трасса неполны или их связь со сборкой не подтверждена.
- `method_coverage_unverified` — покрытие метода трассировкой не подтверждено.

По каждой оговорке сканер показывает отдельный счётчик и отдельно считает
число скрытых объявлений с пустым списком оговорок. Статус `complete` или
`partial` в `.meta.json` относится к целостности всего сравнения. Даже
при `complete` у отдельных объявлений могут быть оговорки о дескрипторе
или покрытии.

## Запуск

Для нового сбора нужны APK, Android-устройство с Frida и собранный образ.
Пути к готовым артефактам позволяют повторить анализ без устройства.
[Сборка образа, запуск с эмулятором и переменные окружения](DOCKER.md)

При наличии локального Python-окружения с зависимостями сканера можно заново
построить отчёты по сохранённому сравнению той же сборки. Поместите рядом с
файлом сравнения его `.meta.json`.

```bash
OUT_DIR=out HIDDEN_IN=out/demo.local.notes.hidden.jsonl bash scan.sh apk/demo.apk
```

Для повторного запуска с готовыми метриками укажите также
`REASONS_IN=out/demo.local.notes.reasons.jsonl`. Сканер проверяет SHA-256 APK и
JSONL по файлу `.meta.json`, а также соответствие записей текущему набору
скрытых объявлений. Срезы аргументов строятся и при таком запуске.

Штатный запуск публикует комплект отчётов после завершения анализа.
`<pkg>.run.json` содержит идентификатор прогона и контрольные суммы. Выходные
имена указывают на одно поколение в скрытом каталоге `.<pkg>.hidden.jsonl.runs/`.
При переносе отдельных файлов используйте копирование с разыменованием ссылок
(`cp -L`) и переносите парные `.meta.json` вместе с JSONL. Прежние списки
`HIDDEN_IN` с подтверждённой сборкой проходят проверку структуры и сохраняют
классификацию исходной сессии. Строки со старым статусом `insufficient_data`
пропускаются с предупреждением. Для пустого списка тип `hidden` обязателен
в метаданных. Чтобы пересчитать её по обновлённым правилам,
передайте `STATIC_IN` и `DYNAMIC_IN` вместо готового списка. Для
`REASONS_IN` нужен отчёт с метриками по DEX-дескриптору.

## Что означают результаты анализа стражей

`reached` показывает наличие прямого вызова конкретной перегрузки в DEX.
Срез аргументов и анализ стражей используют одну сигнатуру: класс, имя метода
и дескриптор. В строке результата `analysis_scope` имеет значение
`dex_descriptor`. Дубликаты каталога сохраняют собственные `declaration_id`. Если дескриптор
не разрешён, строка остаётся в отчётах. Срез аргументов помечается
`dex_method_unavailable`, а в `reasons.jsonl` стоит
`analysis_scope: unresolved` и стоимость `null`.

`entry_evidence` в `reasons.jsonl` хранит независимые оценки для `ui` и
`background`. Значение `resolved` означает найденную цепочку в статической
модели. Значение `modulo_allocation` допускает переход через место создания
лямбды, `possible` допускает более слабые связи, а `not_found` означает, что
в исследованном графе цепочка пока не найдена. `call_site_count` и
`request-slice.jsonl` отдельно показывают ближайшие прямые вызовы.

При интерфейсном вызове слайсер уточняет тип объекта по локальному
`new-instance` и перемещениям регистров. Обработчик `View.OnClickListener`
учитывается как UI-вход, когда анализ связывает конкретное создание объекта
с регистрацией через `setOnClickListener`. Сохранённые отчёты о стражах
без `entry_evidence` нужно построить заново перед использованием `REASONS_IN`.

`guard_count` считает стражи приложения на исследованных путях.
`activation_cost` — нижняя граница минимума в модели. `activation_exact`
показывает, когда анализ установил точное значение. Поле
`best_known_complete_cost` содержит стоимость лучшего найденного полного
пути от подтверждённого callback, либо `null`. Принадлежность метода
экспортированному компоненту сама по себе не доказывает достижимость.
Вызов, наблюдавшийся во время сессии, отмечается отдельно в `hidden.jsonl`.

Тег `dead_end` сохраняется в `notes`. Для обрыва на семантическом кадре
`dead_end:fanin_capped` означает превышение порога числа входящих вызовов через
супертип, а `dead_end:no_callers` — отсутствие вызывающих после поиска.
Разные пути одного ключа могут дать оба тега. Сводка считает каждый тег отдельно.

## Архив

Файлы активации перенесены в `archivive/activate.py`,
`archivive/activate.js` и `archivive/build/activate.js`.
Архивный CLI запускается командой `python -m archivive.activate`.
`build-agents.sh` записывает сборку агента активации в архив.
В приведённых ниже исторических материалах пути активации указаны
относительно прежней структуры проекта.


В `archivive/` вынесен код реконструкции JSON, который используется отдельным
режимом CLI. `body_data.py` содержит прежний анализ DTO,
`body_report.py` — вспомогательный отчёт, `reconstruction.py` — сборку вариантов
и запуск старого режима. Опции `--data-slice`, `--slice-in`, `--serializer`
загружают архивный код по необходимости.

Скрытый запрос — эндпоинт, который есть в коде APK, но ни разу не выполнился при

```
                           (принудительный вызов через Frida: reached/matched/(б1)/(в))
```

1. **`diff.py`** — что из статики реально вызывалось в динамике (Frida), по точному ключу
   `класс->метод`. Даёт список скрытых ключей — вход для `slice.py`.
2. **`slice.py`** — для каждого скрытого ключа статический обратный срез: где он вызывается,
   какие условия (`if`/`switch`) должны выполниться на пути, откуда берутся значения условий
   и аргументов. Не требует устройства — работает по одному APK.
3. **`eval_slice.py`** — детерминированная подвыборка ключей для ручной разметки в JADX и
   скорер precision/recall слайсера против неё (ground truth для RQ2 диплома).
4. **`activate.py` / `activate.js`** — принудительно вызывают скрытый запрос через Frida
   по срезу и измеряют, какой минимальной техникой он активируется (HTTP-аналог Таблицы IV
   ICSE 2025). Требует устройства с frida-server. См. Часть 3.

## Часть 1. `diff.py`: сопоставление статика ↔ динамика по точному ключу

Отличие от `~/hidden_requests/compare.py` (курсовая): там статика и динамика сводились нечётким
сопоставлением URL-путей со скорингом и ~10% погрешности. Здесь сопоставление
**точное по ключу `класс->метод`**: Retrofit строит реализацию API-интерфейса
через `java.lang.reflect.Proxy`, поэтому во Frida доступен сам объект `Method`, а
BFScan печатает ровно тот же ключ. Эвристики не нужны.

**Рассчитано на приложения без обфускации.** Имя метода в DEX совпадает с тем,
что печатает BFScan, а `retrofit2` и `okhttp3` доступны под своими именами. Для
минифицированного приложения (R8 full mode) этого не хватит: имена методов и
аннотаций переименованы, и ключ придётся восстанавливать по значению аннотации.

### Требования

* rooted-устройство или эмулятор, `adb` видит его;
* `frida-server` на устройстве **той же версии**, что `frida` на хосте
  (здесь: 16.7.19, окружение `/home/solidgroup/SolidLab/frida-env`);
* `java` — для BFScan (`BFScan/target/BFScan-3.1.4.jar` — локальный клон
  https://github.com/BlackFan/BFScan; переопределяется `BFSCAN_JAR`).

```bash
adb shell "su -c 'setsid /data/local/tmp/frida-server -D'"
```

### Порядок работы

**Статика и динамика обязаны быть сняты с одной сборки APK.** Иначе набор
эндпоинтов разъедется и отчёт будет врать. Поэтому APK берётся не из магазина, а
прямо с устройства. `trace.py` пишет версию первой строкой NDJSON, `diff.py`
печатает её в шапке отчёта.

1. Вытащить установленный APK:

```bash
adb shell pm path gpm.tnt_premier
adb pull <путь к base.apk> apk/gpm.tnt_premier.apk
```

2. Извлечь статические запросы:

```bash
./bfscan.sh apk/gpm.tnt_premier.apk
```

Даёт `apk/gpm.tnt_premier_methods.md`. Ошибки парсинга XML в логе некритичны —
это ресурсы, не код.

Штатный скрипт передаёт BFScan весь APK, чтобы анализатор видел типы из всех
DEX. После исчерпания памяти возможен запасной разбор отдельных DEX. Его
метаданные содержат `status=partial`, поскольку в таком режиме могут теряться
ресурсы и поля DTO из других DEX.

3. Записать реальный трафик. Исследуйте приложение руками, пока не перестанут
   появляться новые вызовы; `Ctrl-C` завершает запись:

```bash
/home/solidgroup/SolidLab/frida-env/bin/python trace.py --package gpm.tnt_premier
```

Вместо ручного исследования можно подставить GUI-робота в соседнем терминале:

```bash
adb shell monkey -p gpm.tnt_premier --throttle 500 --pct-syskeys 0 -v 380
```

Несколько сессий складываются флагом `--append`.

Если приложение упадёт или его убьёт система, `trace.py` поднимет его сам и
продолжит запись в тот же файл — исследование до насыщения идёт часами, терять
его из-за одного краша нельзя. Уникальные ключи считаются на хосте, поэтому
перезапуск не задваивает счёт. Предел подъёмов задаётся `--max-restarts`
(по умолчанию 10, `0` — не поднимать).

Если в конце прогона появилось `[!] ВНИМАНИЕ: агент упёрся в MAX_EVENTS` —
отчёт использовать нельзя: отброшенное событие неотличимо от скрытого запроса,
то есть результат завышен. Поднимите `MAX_EVENTS` в `hook.js` и повторите.

4. Свести и получить отчёт:

```bash
python3 diff.py --apk apk/gpm.tnt_premier.apk --static apk/gpm.tnt_premier_methods.md \
                 --dynamic out/gpm.tnt_premier.dynamic.jsonl \
                 --out out/gpm.tnt_premier.hidden.jsonl
```

### Что в отчёте `diff.py`

| Секция | Смысл |
|---|---|
| `СКРЫТЫЕ ЗАПРОСЫ` | есть в коде, не вызваны. Класс и метод — это и есть место в APK |
| `ВЫЗВАНО, НО НЕТ В СТАТИКЕ` | класс BFScan знает, а метод — нет: пробел статического анализа |
| `HTTP-ВЫЗОВЫ ВНЕ RETROFIT` | сырой OkHttp, Ktor, WebView, аналитика. BFScan их не извлекает |

### Как устроен `hook.js`

**Слой 1, основной.** Агент наблюдает создание Java-прокси и проверяет
обработчик Retrofit (семейство `retrofit2.Retrofit$`). После установки хука
он регистрирует покрытие интерфейса. Вызов метода записывается с объявляющим
классом, именем, DEX-дескриптором и обработчиком. Это свидетельство вызова
Retrofit-метода; события создания HTTP-запроса и ответа записываются отдельно.

**Слой 2, вспомогательный.** `okhttp3.OkHttpClient.newCall` и
`java.net.URL.openConnection` — полный список URL со стек-трейсами. Нужен не для
ключей, а чтобы измерить, сколько трафика статический анализ не покрывает.
`okhttp3` подгружается лениво, уже после старта процесса, поэтому хук ставится с
повторами (до 60 с), а не один раз при `Java.perform`.

**Предохранитель.** Агент шлёт не больше `MAX_EVENTS` (20000) событий. При
достижении предела он один раз пишет об этом в лог, считает отброшенные и
отдаёт счётчик в `stats()`; `trace.py` превращает это в заметное предупреждение
в конце прогона. Молча обрывать нельзя — потерянный вызов выглядит в отчёте как
скрытый запрос.

### Проверено на пилоте (TNT Premier 2.132.0, code 11134093)

Эмулятор Android 11 x86_64, root. Ручное исследование до насыщения под
авторизацией (вход по номеру телефона), операции оплаты исключены намеренно.

| | |
|---|---|
| Статических записей BFScan | 273 |
| Уникальных ключей `класс->метод` | 198 (75 перегрузок схлопнулось) |
| Вызвано в рантайме | 65 |
| Скрыто | **133 (67.2%)** |
| HTTP-вызовов вне Retrofit | 430 URL, 19 доменов |

Все 65 рантайм-ключей сошлись со статикой дословно — секция «вызвано, но нет в
статике» пуста. При точном сопоставлении по ключу ложных срабатываний нет по
построению.

**67.2% против 67.3% для TNT в курсовой.** Два независимых метода — Burp с
нечётким сопоставлением путей и скорингом против Frida с точным ключом
`класс->метод` — дали одну и ту же цифру.

Покрыто: главная с «Продолжить просмотр», каталог, ТВ-каналы (3 вкладки), спорт,
карточка контента, избранное, оценка, «Просмотрено», поделиться, плеер, история
просмотров, настройки, устройства для загрузки, настройки уведомлений,
переключение между тремя профилями, привязка ТВ и активация промокода с заведомо
неверными кодами, создание детского профиля, смена аватара, удаление профиля.
Последние ключи пришли именно с профильных операций — по одному на действие.

Домены вне Retrofit: `rtbcdn.ru` (CDN, 298 запросов), `tns-counter.ru` (54),
`uma.media`, Crashlytics, `auth.gid.ru`. 430 URL против 65 через Retrofit —
почти семикратный перевес, и ничего из этого BFScan не извлекает.

### Ограничения `diff.py`/`trace.py`

* **Область BFScan** — только аннотации Retrofit/Ktorfit/Feign. У TNT в DEX
  81 вхождение `io/ktor/client/HttpClient` при нулевом `de/jensklingenberg/ktorfit`:
  Ktor используется напрямую, без аннотированных интерфейсов, поэтому его вызовы
  в статику не попадают и видны только в секции «вне Retrofit».
* **Перегрузки.** Ключ `класс->метод` не различает перегрузки (на пилоте 273
  записи дали 198 ключей). Если вызвана одна — FOUND получают все.
* **Только `spawn`.** Retrofit создаёт прокси рано, поэтому подключение к уже
  запущенному процессу их не видит. Проверено: при `attach` к прогретому
  приложению перехватывается ноль вызовов. Режим `--attach` из `trace.py` удалён.
* **Плеер на эмуляторе не работает.** Воспроизведение падает с
  `CHNKLDE_PRMCDN_PR_ANDR`: CDN не отдаёт видеочанки на x86. Вся ветка реального
  просмотра (heartbeat, субтитры, смена качества, продолжение с позиции) остаётся
  недостижимой, и на физическом устройстве доля скрытых была бы ниже. Это ровно
  категория *Device* из таксономии ICSE, воспроизведённая на стенде.
* **`NOT FOUND` ≠ «невозможно вызвать»** — значит лишь, что в рамках этого
  сценария вызов не встретился.
* **Версии сборок.** Всегда тяните APK с устройства — сборка в магазине может
  быть старше установленной.
* **BFScan молчит при OOM.** Код возврата 0, файл обрезан. Единственный признак —
  строка `OutOfMemoryError` в логе, поэтому запускать только через `bfscan.sh`.

## Часть 2. `slice.py`: статический обратный срез скрытых запросов

В основном конвейере `scan.sh` запускает этот движок через `request_pipeline.py`
сразу после среза аргументов. Оба этапа используют один разбор DEX. В
`reasons.jsonl` попадают метрики анализа и причины остановки. Отдельный
исследовательский CLI сохраняет подробный `slice.jsonl`; его формат описан ниже.

Для каждого скрытого ключа `class->method` движок восстанавливает: где он вызывается в байткоде (call-sites через XREF androguard),
обратным межпроцедурным обходом — управляющие стражи на пути (`if`/`switch`, через
пост-доминаторы CFG) и происхождение операндов условий и аргументов вызова
(константа / поле / возврат метода / `instanceof`-проверка типа / параметр / неизвестно). Не требует устройства
или трафика — работает по одному APK. Полный дизайн и обоснование выбора
androguard+networkx вместо Soot/FlowDroid — в
`docs/superpowers/specs/2026-09-28-static-backward-slice-design.md`.

Результат — HTTP-аналог Таблицы IV из ICSE 2025 (доля запросов, активируемых
без условий / с 1–2 условиями / со многими условиями) для главного количественного
вопроса диплома (`CONTEXT.md` §4.3).

### Отдельный запуск CLI для подробного среза

```bash
python3 slice.py --hidden out/gpm.tnt_premier.manual.hidden.jsonl \
                  --apk apk/gpm.tnt_premier.apk \
                  --out out/gpm.tnt_premier.slice.jsonl
```

Загрузка APK через androguard занимает ~1.5–2.5 минуты на 130-МБ multi-dex
приложении (один раз на весь прогон). Пишет `<out>.jsonl` (по записи на ключ) и
`<out без .jsonl>.report.txt` (сводка + распределение по числу стражей).

Проверка без APK (алгоритмика на синтетических графах, секунды):

```bash
python3 slice.py --selfcheck
```

С APK (те же проверки + интеграция против реального DEX, ~1.5–2.5 мин):

```bash
python3 slice.py --selfcheck --apk apk/gpm.tnt_premier.apk
```

### Формат `slice.jsonl`

Одна запись на ключ: `key`/`cls`/`method`, `reached` (есть ли хоть один call-site),
`call_sites` (вызывающий + смещение), `guards` (список стражей: opcode, взятая
ветвь, источник операнда — `{source_kind, detail}`, `notes`), `guard_count`
(объединение реальных стражей всех путей — ВЕРХНЯЯ оценка), `activation_cost` +
`activation_exact` (минимум реальных стражей по путям от UI-входа — стоимость
активации; `exact=true` ⇒ точно, иначе нижняя оценка или `null`), `args` (источники
аргументов вызова — ось «нужны ли данные»), `frontier` (где обход остановился),
`depth`, `plumbing_skipped`, `inconclusive`, `notes`.

**Два вида стражей отфильтрованы из `guard_count` намеренно**, но не выброшены —
помечены в `notes` и видны в полной записи:
- `coroutine_state_machine` — диспетч по `label`-полю корутины
  (`invokeSuspend`/`invoke`/`create` на self-поле собственного кадра, а также
  пролог suspend-функции: `cont instanceof K`, чтение `K.label` и его знаковая
  проверка `if ((label & MIN_INT) != 0)`, где `K` — класс с `invokeSuspend`) —
  не условие активации, а служебный переключатель стейт-машины Kotlin;
- `framework` — стражи на `android.*`/`androidx.*`/`java.*`/`kotlin.*`/
  `kotlinx.*` и компиляторных проверках (`Intrinsics.areEqual`,
  `checkNotNull*`, `Enum->ordinal`), а также любые ветвления в кадрах самого
  фреймворка — не гейты приложения, а рантайм/UI-код (обход `View`,
  null-safety-проверки Kotlin).

Оба счётчика (`guard_count_coroutine`, `guard_count_framework`) сохранены в
записи отдельно — видно, насколько велик отфильтрованный шум.

### Пилот (TNT Premier 2.132.0, та же сборка, что и у `diff.py`)

133 скрытых ключа из `out/gpm.tnt_premier.manual.hidden.jsonl`, прогон v5 (2026-10-06, с CHA):

| | |
|---|---|
| reached / no_caller / key_not_in_dex | 119 / 12 / 2 |
| обход оборван не на фронтире (`dead_end`) | 100 |
| `guard_count` — объединение, верхняя оценка (0/1/2/3/4+) | 32 / 6 / 1 / 6 / 74 |
| **`activation_cost` — минимум по путям, ТОЧНО (Таблица IV), 29 ключей** | **22 / 1 / 3 / 1 / 2** |
| нижняя оценка (не дошёл до UI) / не определена | 89 / 1 |

Полный отчёт — `out/gpm.tnt_premier.slice.report.txt`. Прогоны v1–v4 сохранены как
`*.slice.v{1..4}.*`; v1 («0→76», выброс 528) **недействителен**. v4 добавил главную метрику —
**стоимость активации (минимум реальных стражей по путям от UI-входа)**; v5 добавил CHA-резолв
полиморфных вызовов: 22 из 29 ключей с точной стоимостью активируются без единого гейта
приложения. Разбор v1→v5 — `CONTEXT.md` §4.7, `docs/slice-methodology.md` §6–7.

### Важные оговорки к пилоту (прежде чем цитировать числа в тексте ВКР)

1. **Таблица IV точна только для 29 из 119 ключей** (дошли до UI-входа, `activation_exact`).
   Остальные: 89 — нижняя оценка (обход не дошёл до UI), 1 — стоимость не определена.
2. **`dead_end` у 100/119 ключей.** CHA-резолв полиморфных вызовов реализован (прирост 27→29);
   ограничитель покрытия **архитектурный** — сетевые вызовы идут через разделяемые DI/clean-arch
   интерфейсы, которые потолок fan-in CHA отсекает. Углубление обхода проверено и не помогает.
3. **Ground truth (§8 дизайна, RQ2) не прогнан.** С минимумом по путям размечать осмысленно
   на 27 `activation_exact`-ключах:

```bash
python3 eval_slice.py --pick --hidden out/gpm.tnt_premier.hidden.jsonl
# -> 18 детерминированных ключей (seed=42) для ручного разбора в JADX
# результат разметки: out/tnt_truth.json — {key: [[source_kind, detail], ...]},
# detail можно писать как в JADX (Cfg.mode, SessionManager.isLoggedIn()) — скорер
# сводит его с дескрипторами androguard к виду Cls.member
python3 eval_slice.py --slice out/gpm.tnt_premier.slice.jsonl --truth out/tnt_truth.json
# -> precision/recall детекции стражей
```

Для ручной разметки `--pick` по умолчанию выбирает скрытые записи с
`confidence_caveats: []`. Флаг `--include-caveats` включает также записи с
оговорками и старые записи, в которых этого поля ещё нет.


### Ограничения `slice.py` (осознанные, помечены `ponytail:` в коде)

* Обратный обход источника значения (def-use) — на один семантический хоп;
  длинная цепочка присваиваний до условия даёт `unknown`.
* Перегрузки не различаются (как в `diff.py`): ключ — `класс->метод`.
* `_params` не восстанавливает второй (старший) регистр wide-параметров
  (`long`/`double`) — не влияет на bool/int-флаги, основной источник стражей.
* `is_plumbing` определяет корутинную машинерию по имени метода/класса —
  не по суперклассу; может пропустить плумбинг-кадр на нестандартной
  обфускации (компенсируется п. «coroutine_state_machine» выше — такой кадр
  не выбрасывается, а флагуется).
* `reached=false`/`inconclusive` ≠ «невозможно вызвать» — только «статически
  не разрешено в рамках этого анализа» (тот же смысл, что `NOT FOUND` у
  `diff.py`).

## Часть 3. `activate.py` / `activate.js`: принудительная активация

Следующее звено после среза: взять скрытый ключ и его срез (`slice.jsonl`) и
**принудительно вызвать запрос через Frida**, подтвердив достижимость динамически.
Это HTTP-аналог RQ3 / Таблицы IV из ICSE 2025 (перспектива №2 курсовой). Подробный
журнал реализации и честные оговорки — `CONTEXT.md` §4.8; дизайн —
`docs/superpowers/specs/2026-10-16-frida-forced-activation-design.md`.

**Как это работает.** `activate.js` — фиксированный Frida-рантайм; `activate.py` —
оркестратор. На каждый ключ пробуются **ступени** снизу вверх (0 — прямой вызов
Retrofit-метода; 1 — ближайший вызывающий + форс стражей; 2 — UI-фронтир), берётся
минимальная сработавшая. Аргументы объектных request-body-DTO **конструируются**
(`$new` с рекурсивным синтезом полей из `arg_recipes` среза), а не берутся из кучи
(транзиентные DTO там отсутствуют). Retrofit-прокси минтится из живого
`retrofit2.Retrofit`-синглтона (`retrofit.create(Iface)`), если на холодном старте
сервис ещё не инициализирован. Возвращённый вызовом объект **отправляется на провод
по типу возврата**: `retrofit2.Call`→`enqueue`, RxJava→`subscribe` (без этого
не-suspch методы строят `Call`, но запрос не уходит). Подтверждение — key-exact
оракул (хук `InvocationHandler.invoke`); фактический исходящий запрос снимается на
сборке (`Request$Builder.build`) и диспетче (`okhttp.newCall`) и эмитится сразу
(push-захват), чтобы пережить краш приложения до снятия снимка.

**Уровни успеха** (в отчёте, взаимоисключающе):
* **reached** — форс дошёл до Retrofit-метода (вход в прокси); НЕ гарантирует запрос.
* **matched** — запрос реально ушёл на нужный endpoint (снимок `matched`), из них:
  **(б1)** реальные app-данные · **(в)** synthesized (наши `$stub`) · бинарное
  (protobuf/gRPC) / пустое тело.

**По умолчанию — механический бэкенд без LLM** (`--backend mech --recurse-args`).
Опционально `--backend openai`/`manual`/`plans` (LLM выдаёт декларативный JSON-план,
строго валидируемый против DEX до касания устройства).

### Запуск

```bash
./build-agents.sh                      # пересобрать build/*.js ПОСЛЕ правок *.js (frida 17!)
.venv/bin/python activate.py --selfcheck
.venv/bin/python activate.py \
  --slice out/<pkg>.slice.jsonl --apk apk/<pkg>.apk --package <pkg> \
  --hidden out/<pkg>.hidden.jsonl --backend mech --recurse-args --skip-dx \
  --attach --non-interactive --out out/<pkg>.activation.jsonl
```

> **Критично (frida 17):** рантайм грузит **скомпилированный** `build/activate.js`
> (бандл с `frida-java-bridge`), а НЕ исходник. После любой правки `*.js` обязателен
> `./build-agents.sh`, иначе изменения — тихий no-op. Это же касается Docker-образа
> (`COPY . /app` печёт `build/` как есть — см. `DOCKER.md`).

`--attach` цепляется к уже запущенному приложению без рестарта между ключами;
`--non-interactive` — после краха форсом поднимает свежим без ожидания человека;
`--keys`/`--keys-file` — подвыборка; `--all-reached` — все достижимые ключи.

### Результаты (device-verified)

| Приложение | reached | matched (запрос ушёл) | из них (б1)/(в) |
|---|---|---|---|
| TNT Premier 2.134.0 (suspend/Retrofit) | 47/48 | — | (б1) 10 |
| ivi `ru.ivi.client` (Call+RxJava, protobuf) | 101/118 | **79/118** | (б1) 2 / (в) 39 |

Уровень (б2) «наполнить реальными user-данными» механически **не берётся** — это
прямой HTTP-аналог тира «+Data support» RQ3 ICSE (сессия/логин, выбранный id, PIN,
платёжные данные). `CONTEXT.md` §4.8 — полный разбор границы.

### Ограничения `activate.py`/`activate.js`

* **Ступень 0 завышает достижимость** — прямой вызов обходит всю логику; заголовочная
  метрика — matched (запрос на проводе), а не reached.
* **Нестабильность эмулятора.** Десятки force-stop+spawn на крэш-ключах замораживают
  Genymotion в `offline` — лечится перезапуском VM (`gmtool admin stop/start`) +
  подъёмом frida-server. Прогон вести батчами с проверкой `adb devices`.
* **Корректный хост требует тёплого состояния** — на холодном старте feature-Retrofit
  ещё не создан, форс уходит на первый живой инстанс (сторонний SDK); path/body верны.
* **protobuf-тела нечитаемы** (`<unreadable>`) без `.proto`-схем (в APK их нет) —
  запрос засчитывается matched, но тело не рендерится в текст.
* **~35% не-matched** — сложные DTO/параметры, которые сборщик аргументов не осилил
  (предел статического синтеза среза), либо suspend/Call не дошёл до сети.
